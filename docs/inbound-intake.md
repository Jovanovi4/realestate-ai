# Входящие обращения

## Публичные формы

В редакторе объекта откройте «Лендинг» → «Блоки лендинга» и включите «Подбор и обращение собственника». Этот блок управляется отдельно для каждого объекта; на существующих лендингах он выключен. На публичной странице посетитель выбирает «Подобрать другую недвижимость» или «Продать или сдать свой объект» и заполняет одну раскрытую форму, оставаясь на лендинге. Основная заявка по рекламируемому объекту работает отдельно.

Форма проверяет согласие, ограничение частоты и Turnstile, если он включён. Случайный идентификатор отправки защищает от повторного создания записи. Запрос подбора создаёт заявку без выбранного объекта, запрос собственника — обращение в общем списке «Заявки». Оба получают источник «Лендинг» с названием и ID исходной страницы и срок первого ответа через 30 минут. Ответственным становится риелтор исходного объекта; для командного объекта без действующего участника назначается владелец команды.

Ранее опубликованные прямые ссылки на самостоятельные формы продолжат работать и сохранять источник «Публичная форма», но отдельный блок управления ими больше не показывается в списке лендингов. Уже существующая история не переписывается.

## Входящая почта

Почтовый импорт опционален. Используйте отдельную IMAP-папку, в которую правилами почты помещаются **только** обращения для одного рабочего пространства. Импорт не читает другие папки и не удаляет письма. Пока письмо не разобрано, оно ещё не является заявкой; если такие письма есть, на странице «Заявки» появляется значок почты со счётчиком. Риелтор проверяет телефон и выбирает «Подбор недвижимости» или «Хочу продать / сдать». Текст письма уже подставлен. Если письмо не относится к CRM, его можно отклонить. В записи сохраняются отправитель и тема как уточнение источника. Отсутствие согласия не заменяется автоматической отметкой.

Для Яндекс Почты включите IMAP-доступ, создайте отдельный пароль приложения и папку `REAICRM`. [Официальные параметры Яндекса](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others): `imap.yandex.ru`, SSL, порт 993. В `.env.docker` или в локальном закрытом окружении задайте:

```dotenv
INBOUND_IMAP_HOST=imap.yandex.ru
INBOUND_IMAP_USER=адрес_почты
INBOUND_IMAP_PASSWORD=пароль_приложения
INBOUND_IMAP_FOLDER=REAICRM
INBOUND_IMAP_LINK_CODE=код_PublicIntakeLink_нужного_пространства
```

Код пространства можно посмотреть в карточке `PublicIntakeLink` в Django admin. Пароль не передавайте в чат и не добавляйте в Git. Для одного пробного чтения на пилоте после перезапуска `web`:

```bash
sudo docker compose --env-file .env.docker exec web python manage.py fetch_inbound_email --limit 20
```

Команда сохраняет `UIDVALIDITY` и последний UID папки. Повторный запуск продолжит с последнего успешно сохранённого письма; уникальность события дополнительно защищает от дублей. Постоянное расписание включайте после проверки папки и нескольких тестовых писем. Один набор `INBOUND_IMAP_*` обслуживает одно пространство; для нескольких ящиков нужны отдельные процессы с отдельными переменными.

## Совпадения контактов

В обзоре контакта показываются возможные совпадения по нормализованному телефону или имени. Объединение выполняется только после просмотра обоих контактов. В личной базе его делает владелец, в командной — владелец или руководитель. Заявки, обращения, задачи, сделки, история, собственность и предложения переходят в основную карточку. Если у обоих контактов есть активная сделка по одному объекту или другая запись с уникальным ограничением, объединение останавливается до ручного решения. Журнал объединения сохраняет исходные имя, телефон и количество перенесённых записей.

## Площадки

Для Циан в [официальной документации API](https://public-api.cian.ru/docs/latest) описаны входящие webhook-сообщения. Их подключение требует доступа API конкретного аккаунта, соответствия объявлений объектам CRM и проверки подписи/происхождения доставки. Для Авито также нужен подтверждённый доступ к официальному каналу сообщений конкретного аккаунта. До получения доступов никакой неофициальный парсинг площадок не включён. Модель входящих событий уже поддерживает отдельные каналы `avito` и `cian` с уникальным внешним ID.
