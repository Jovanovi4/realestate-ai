# Тариф и расход: состояние, ресурсы и ИИ-кредиты

Этап 4.2, 29 сентября 2026 года. Основа — [BP-0.1](billing-policy.md),
[модели и правила](billing-foundation.md), [наблюдательный учёт](billing-metering.md).

Раздел `/billing/` доступен после входа по ссылке в личном кабинете.
Показывает текущий тариф, состояние доступа, даты назначенных периодов,
расход ресурсов и остаток ИИ-кредитов.
**Тарифные ограничения и платежи по-прежнему не включены.**
Стоимость генерации до запуска будет отдельным шагом.

В карточках оставлены короткие заголовки и основные числа. Пояснения к
разделам и периодам открываются значком ⓘ по нажатию, касанию или с
клавиатуры. Короткие описания объектов, лендингов, мест и хранилища постоянно
видны под счётчиками; подробные правила учёта доступны в подсказке заголовка
«Ресурсы». Счётчики расположены в две колонки при достаточной ширине, а
кредиты и даты — рядом. Нулевой ожидаемый расход ИИ и часовой пояс без дат
не показываются. Предупреждения о неполном учёте, превышении и состоянии
доступа остаются видимыми без раскрытия подсказок. При наличии команды
личный и командный тарифы переключаются вкладками в стиле карточки объекта;
без команды показывается одна карточка без переключателя.

## Рабочие пространства и права

- Личная область и текущая команда отображаются в отдельных вкладках.
- Командную карточку видят действующие участники, включая руководителя и
  риелтора. Оплата за команду сама по себе не даёт доступа к этой карточке.
- Пользователь не выбирает произвольный счёт по URL или параметрам запроса.
  Пространства определяются по его личности и текущему членству.
- После исключения из команды её вкладка больше не отображается.
- Основания назначения/приостановки/аннулирования, плательщик, UUID операций
  и технический журнал пользователю не передаются.
- Ответ запрещает сохранение страницы в кэше через `Cache-Control: no-store`.

Открытие раздела только читает БД. Оно не создаёт счёт, грант Демо,
подписку или период, не запускает сверку, не меняет бюджеты и CRM.
Для пространства без созданного счёта показывается Демо из текущего каталога.
Если каталог или условия невозможно проверить, отображается состояние
«Требует проверки» без выдуманного тарифа и дат.

## Тариф и даты

`billing.presentation.subscription_summary` получает состояние из
`PolicyService.context`, используя одно время проверки для всех карточек.

| Состояние | Отображение |
| --- | --- |
| `demo` | Демо, бесплатный бессрочный доступ без расчётного периода |
| `active` | Тариф текущего периода, его начало и окончание |
| `grace` | Тариф завершённого периода, прежние даты и отдельное окончание льготного срока из снимка условий |
| `restricted` | Возврат на Демо; последний неаннулированный завершённый период показан отдельно |
| `suspended` | Приостановка; если есть текущий назначенный период, сохраняется название его тарифа и даты с этой пометкой |
| `unknown` | Сообщение о необходимости проверки |

Название назначенного тарифа при приостановке — информация о периоде;
оно не изменяет решение сервиса о доступе. Вся страница информационная:
состояния тарифного слоя не вводят блокировки действий в кабинете.

Будущий неаннулированный период показан отдельно как «Следующий
период» и не заменяет текущий тариф до наступления начала. Источник периода
показан как «Пилотный доступ» или «Назначение оператором»; это не подтверждение
оплаты. Аннулированные периоды не отображаются как доступ.

Интервалы остаются `[starts_at, ends_at)`. Даты форматируются в текущем часовом
поясе Django с учётом перехода на летнее время; его имя указано на странице.
Границы рассчитываются сервисом по текущей дате без фоновых заданий.
Страница не применяет запланированную смену тарифа, отмену или автопродление.

## Счётчики ресурсов

`billing.rules.collect_usage` считает текущие записи по одной области: личные
`owner=user, agency=None` либо записи команды. Счёт может ещё не существовать;
тогда используются серверные данные области без создания счёта.

- Объекты: все неархивные, включая черновики, завершённые и демо. Архив
  указан отдельно в пояснении и не расходует место активных карточек.
- Лендинги: намерения публикации неархивных объектов.
- Места: владелец/действующие участники плюс непринятые приглашения, срок
  которых ещё не истёк. Принятое приглашение не занимает второе место.
- Хранилище: байты сохранённых фото и логотипов по реестру файлов, в том числе
  архивных и файлов без актуальной ссылки. Один ключ считается один раз.
  При неполной инвентаризации или неизвестном размере на странице написано
  «Объём уточняется». Нулевой объём допустим только при полной проверке.

Лимиты берутся из снимка действующего периода, текущего Демо или назначенного
периода при приостановке. При ошибке условий показан фактический счётчик без
выдуманного лимита. График ограничен 100% ширины, но само превышение показано
числом и пояснением. Хранилище форматируется в бинарных КБ/МБ/ГБ;
сравнение с лимитом выполняется по точным байтам. Время последнего обновления
инвентаризации не обещает проверки физического файла именно в этот момент.

## Остаток ИИ-кредитов

Баланс относится к текущему платному периоду либо одному личному гранту Демо.
Грант и платный месячный бюджет не складываются; команда не получает личный
бонус сотрудника. Успешные наблюдаемые списания прибавляются к финансовым
счётчикам, а ожидаемый расход операций `running` и `unknown` вычитается из
показанного остатка предварительно. Подлинный резерв бюджета, если он есть,
показан отдельно. Одна операция комплекта не умножается на число результатов.
Ошибка и отменённая генерация не становятся успешным списанием.

Остаток — `max(0, начислено − использовано − резерв − ожидаемый расход)`.
При превышении ноль не маскирует превышение: оно показано отдельно.
Неизвестный исход генерации отмечен для проверки. Открытие страницы не
выдаёт грант; неподтверждённый email получает ссылку в личный кабинет,
а подтверждённый аккаунт без гранта видит, что бонус ещё не начислен.

В льготный срок расход сохраняется за завершённым периодом. После него на
Демо показывается прежний остаток личного гранта и расход последнего
платного периода отдельно; новый месяц не наследует расход предыдущего.
При приостановке действующий назначенный бюджет указан с пометкой.
Отключение наблюдательного учёта явно помечает ИИ и файлы как потенциально
неполные. Исторические генерации до включения журнала не тарифицируются.

## Проверка

```bash
python manage.py test billing.test_overview billing.test_usage_overview
python manage.py test
python manage.py makemigrations --check --dry-run
python manage.py check
```

Покрыты отсутствие счёта, действующий/будущий/завершённый/аннулированный период,
границы срока и льготы, приостановка, календарные даты/часовой пояс, командные
роли, отзыв членства, отсутствие прав у отдельного плательщика, ошибки условий
и отсутствие записей в БД при GET. Проверены личные/командные ресурсы,
архив, приглашения, инвентаризация, бинарные единицы, превышение, ИИ-комплект,
ожидаемые/неизвестные операции, месячная граница и возврат к Демо.
Новых миграций для этого шага нет.

Следующий шаг — стоимость ИИ-действия до запуска, атомарные резервы и защита
от повторных запросов, проверка конкуренции и отдельное подключение ограничений.
