# Проверка аналитики на пилоте

Команда `audit_crm_analytics` только читает БД. Она сравнивает ключевые числа
отчёта с выборками, на которых построены реальные списки «Заявки» и «Сделки»:
поступившие и обработанные заявки, заявки без ответа, заявки по источникам,
созданные сделки и текущие этапы. Для обращений собственников берётся базовая
выборка их списка с правилами периода и исключения демо. Дополнительно
проверяется, что сумма заявок по строкам объектов равна итогу периода.
Команда выводит только числа, технические ID пространства и время запросов;
имена, телефоны, адреса и SQL с параметрами не печатаются. При расхождении
завершается с ненулевым кодом. На PostgreSQL все сравнения выполняются в одной
read-only транзакции с уровнем `REPEATABLE READ`, чтобы новая заявка между
двумя запросами не дала ложное расхождение.

После доставки **этой версии кода** на пилот, проверенной резервной копии и
применения миграций выполнить от пользователя с доступом к Docker:

```bash
cd ~/realestate-ai
sudo docker compose --env-file .env.docker exec -T web \
  python manage.py audit_crm_analytics --user-id ID_ВЛАДЕЛЬЦА --scope personal
sudo docker compose --env-file .env.docker exec -T web \
  python manage.py audit_crm_analytics --user-id ID_ВЛАДЕЛЬЦА --scope team
sudo docker compose --env-file .env.docker exec -T web \
  python manage.py audit_crm_analytics --user-id ID_СОТРУДНИКА --scope team
```

Если руководитель выбирает сотрудника, добавить `--member-id ID_СОТРУДНИКА`
к командной проверке от его собственного `--user-id`. Запрос чужого `member-id`
от имени агента не расширяет доступ: эффективный `member_id` в ответе останется
ID агента. Повторить проверки для 7, 30 и 90 дней через `--days`. Перед
обсуждением результата удалите из вывода технические ID, если хотите показать
его за пределами команды.

`performance.analytics_*` измеряют только расчёт агрегатов;
`page_*` — полный серверный ответ страницы «Аналитика», включая шаблон и
разбивку по сотрудникам; `full_audit_*` включают дополнительные сверочные
запросы, но не повторную отрисовку страницы. Запустите команду трижды на
тёплой базе и сравните длительности. Для небольшого пилота
более 1 секунды или более 60 SQL-запросов на страницу — повод разобрать планы
PostgreSQL и объём данных, а не автоматически добавлять индексы. Отдельно
проверьте большой интервал 90 дней, много обращений с первым ответом и много
обращений собственников: медиана ответа и просрочки сейчас проходят по
результирующим строкам в Python. Проверка прав должна включать владельца,
сотрудника и пользователя без команды; тесты проверяют также CSV с подставленным
`member-id`. Отчёт не измеряет браузерную отрисовку.

Локально на SQLite команду можно проверить с `--allow-sqlite`, но её скорость
не заменяет проверку пилотной PostgreSQL. На 12 октября 2026 года локальная
сверка личных и командных пространств прошла без расхождений; расчёт
агрегатов выполнял 38 SQL-запросов, серверная отрисовка личной и командной
страницы — соответственно 50 и 55 запросов на небольшой SQLite-базе.
Проверка на
реальной PostgreSQL **ожидает доставки кода на пилот**. Пароли, `.env.docker`
и полные выгрузки CRM для этой проверки передавать не нужно.
