# Резервная копия пилота на PostgreSQL

`backup_crm` рассчитана на локальную SQLite. Для Docker-пилота используйте
`deploy/backup_verify_pilot.sh` от пользователя `deploy` (без `sudo` перед
самим скриптом). Нужны доступ `sudo docker`, Python 3.12+ и уже запущенный
Compose-стек. Значения `.env.docker` не выводятся в журнал.

```sh
cd ~/realestate-ai
bash deploy/backup_verify_pilot.sh
```

По умолчанию копия помещается в приватный каталог `~/reaicrm-backups/` вне
проекта, медиа и веб-корня. Можно передать абсолютный путь к другому закрытому
каталогу первым аргументом. Во время копирования `web`, `outbound`,
`publications` и работающий `account-emails` кратко останавливаются; сайт и
бот в это время недоступны.
Скрипт возвращает в работу только процессы, которые были запущены до копии,
даже при ошибке. Не запускайте несколько копий
одновременно.

В каталоге копии сохраняются `database.dump` (формат PostgreSQL custom),
`media.tar.gz`, контрольные суммы и числа записей. Скрипт восстанавливает БД
в одноразовом контейнере PostgreSQL 17 без сети, сравнивает числа ключевых
записей, извлекает медиа во временный каталог, сверяет их SHA-256 и наличие
файлов, на которые ссылается восстановленная база. Он не подключается к
боевой БД для восстановления и не удаляет старые копии. Только успешная
проверка создаёт файл `VERIFIED`.

Если проверка прервалась, каталог остаётся для разбора без `VERIFIED`;
не считайте его рабочей копией. Убедитесь, что `web`, `outbound`,
`publications` и `account-emails` (если он был запущен) снова работают через
`docker compose --env-file .env.docker --profile mail ps`.
Проверка архива медиа отклоняет ссылки и небезопасные пути. Если она нашла
отсутствующий файл, сначала разберите расхождение между БД и томом `media`.

Скрипт проверяет восстановление **на этом же VPS**, что защищает от ошибки
копирования, но не от потери самого сервера. После успешной проверки
зашифрованную копию БД/медиа и отдельно сохранённые секреты `.env.docker`
нужно вывезти в закрытое внешнее хранилище; права на каталог ограничить.
Для реального пилота затем настройте [зашифрованные внешние копии и расписание](docker-offsite-backups.md),
удержание нескольких копий и периодическое восстановление вне боевой среды.
`pg_dump` сохраняет одну
БД, а не глобальные роли кластера; при развёртывании нового Compose-стека
роль создаётся из настроек `POSTGRES_USER`/`POSTGRES_PASSWORD`.

После появления `VERIFIED` переходите к [проверке тарифных ограничений](docker-billing-pilot.md)
на отдельной тестовой базе PostgreSQL и сверке счетов пилота.

Используется [custom dump и `pg_restore` PostgreSQL 17](https://www.postgresql.org/docs/17/backup-dump.html).
