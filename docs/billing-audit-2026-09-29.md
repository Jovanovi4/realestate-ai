## Счета и возможное влияние ограничений

| Показатель | Результат |
| --- | ---: |
| Счета | 7: 5 личных и 2 командных |
| Тарифное состояние | Все 7 — Демо |
| Полнота реестра файлов | 7 из 7 счетов: ссылки и размеры известны |
| Ошибки проверки привязанных файлов | 0 |
| Неизвестные / выполняющиеся ИИ-операции | 0 / 0 |
| Счета с превышением числового лимита | 1 |

Личный счёт **#2** использует 2 активных объекта из 2 и 2 публичных лендинга
из 1. Если включить действующее правило сейчас, новые объекты и публикации
будут запрещены, а обе уже опубликованные страницы этого счёта получат
нейтральный ответ 503 до выбора страницы в пределах квоты или изменения тарифа.
Остальные счета не превышают лимиты объектов, лендингов, мест или привязанного
хранилища. Один командный счёт использует 1 лендинг из 1 и не сможет
опубликовать ещё один на Демо.

Разовый Демо-грант на 5 ИИ-кредитов есть у одного личного счёта; расход и резерв
равны нулю. У остальных шести счетов выделено 0 кредитов. При включении
ограничений генерация на них будет недоступна до предоставления права на
кредиты. На Демо также недоступны новые приглашения в команду и XML-экспорт;
существующие данные не удаляются. Это влияние правил тарифа, даже когда
числовая квота счёта не превышена.

В каталогах `media/properties` и `media/landing_logos` найдено **810 файлов,
91 475 147 байт (87,24 МиБ)** без записи `StoredFile`. Ошибок чтения и
недоступных элементов при обходе нет.

| Нет ссылки из текущих записей БД | 807 | 90 348 465 байт | Приписать пользователю или считать занятым местом счёта нельзя |

У 807 файлов без ссылки только **8 разных содержимых** (сравнение SHA-256).
291 файл, 89 957 412 байт, побайтно совпадает с тремя статическими демо-фото.
Дополнительная проверка показала: у всех 291 файла имя, создаваемое сервисом
демо-данных (`demo-demo-*`); это 97 копий каждого исходного фото. Ни один из
этих путей не встречается в файловых или текстовых полях текущей БД. Один
другой экземпляр демо-фото используется действующим объектом и в эту группу
не входит. Остальные
516 файлов занимают 391 053 байта. Исходное назначение этих файлов также не
установлено. При первичной сверке ничего не удалялось и не перемещалось.

Обычная регистрация пользователя не создаёт файлы. Три фото копируются только
при явном POST «Начать с демо»; повторный запрос того же пользователя новых
копий не создаёт. Сервис использует общие исходные имена, поэтому файловое
хранилище добавляет уникальный суффикс новым копиям. Накопление 97 наборов
согласуется с многократными запусками теста демо-кабинета, который раньше
записывал фото в постоянный `MEDIA_ROOT`, тогда как тестовая БД после прогона
удалялась. Это наиболее вероятный источник, но исторический источник каждой
копии отдельно не записан. Проверены и пройдены тесты регистрации, первого
запуска демо и повтора; они теперь используют временное media-хранилище.

Перенос **именно этих 291 неиспользуемых копий** не нарушает ссылки текущего
приложения: их нет ни в одном `FileField`, `StoredFile` или текстовом поле БД;
исходные статические фото и рабочий файл демо-объекта остаются. Проверенная
резервная копия содержит копии на случай восстановления. Старые прямые ссылки
на `/media/...`, сохранённые вне приложения, после удаления недоступны; их
существование нельзя исключить. Манифест удаления хранит исходные пути и
хеши для восстановления из резервной копии.
Это заключение **не относится** к остальным 519 файлам вне реестра, включая
три фото объектов без владельца.

Пять объектов без владельца не входят ни в один тарифный счёт. Три их фото
физически существуют и остаются в проверенной резервной копии. Назначать этим
объектам произвольного владельца нельзя: сначала нужен подтверждённый источник
их происхождения. Все пять — черновики без опубликованных лендингов.

## Что сделано и что остаётся

Тесты карточек объектов теперь используют временный `MEDIA_ROOT` на каждый
тест. Повторный запуск 59 тестов не увеличил число или объём файлов вне
реестра: осталось 810 файлов и 91 475 147 байт.

После проверки 291 копия демо-фото перенесена из рабочего media в закрытый
карантин `.crm-backups/quarantine-demo-xw61ujj8`. Манифест содержит исходный
путь, размер и SHA-256 каждого файла; все 291 хеша после переноса совпали.
Затем только эти 291 файла удалены из карантина после повторной проверки их
копий в резервной копии. Манифест сохранён. Рабочее фото действующего
демо-объекта осталось на месте. Повторный отчёт показывает
**519 файлов вне реестра, 1 517 735 байт**: три фото старых объектов без
владельца и 516 файлов без ссылок. Проверенная резервная копия до переноса
содержит все 819 тогдашних файлов media и осталась доступна.

Перед дальнейшей очисткой требуется отдельное решение о судьбе оставшихся
516 файлов без ссылок и подтверждение владельца либо архивного статуса пяти
старых объектов. Пока эти данные сохраняются. Перед включением тарифных
блокировок также нужно урегулировать счёт #2 (выбор одного лендинга или другой тариф), проверить
ожидаемую доступность ИИ на шести счетах без гранта и выполнить испытания на
отдельной PostgreSQL, описанные в [плане внедрения](billing-enforcement.md).
