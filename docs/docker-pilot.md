# Пилотный сервер с Docker и чистой PostgreSQL

Конфигурация собирает **текущую версию репозитория** в образ Django и запускает
пилот на одном VPS. Локальная SQLite и каталог `media/` в образ не попадают.
Маркетинговый сайт пока не входит в этот стек: Caddy обслуживает CRM и публичные
лендинги объектов на одном адресе.

## Сервисы и данные

- `web`: Gunicorn с двумя процессами и двумя потоками в каждом. Генерация через
  OpenAI пока выполняется внутри HTTP-запроса, поэтому таймаут — 150 секунд.
- `migrate`: отдельный одноразовый запуск миграций. Сборка образа устанавливает
  зависимости и собирает статику, но не меняет базу данных.
- `db`: PostgreSQL 17 с постоянным томом `pgdata`.
- `redis`: общий кэш для ограничений входа и публичных форм. Краткоживущие
  данные кэша намеренно не сохраняются при перезапуске.
- `proxy`: Caddy получает и обновляет сертификат HTTPS, передаёт запросы Django
  и читает `/media/` из постоянного тома только для чтения. `/static/` обслуживает
  WhiteNoise из образа приложения.

В интернет открыты только порты Caddy: 80 и 443. PostgreSQL и Redis находятся
во внутренней сети Docker. Для запросов OpenAI и Telegram контейнер `web`
использует исходящее соединение. Исходный код и секреты хоста в `web` не
монтируются.

## До первого запуска

1. Установите Docker Engine и плагин Compose на VPS. Направьте постоянный
   DNS-адрес на IP сервера и откройте TCP 80/443 и UDP 443. Домен пока не выбран,
   поэтому HTTPS-прокси сейчас запустить нельзя.
2. Скопируйте `.env.docker.example` в `.env.docker`, задайте права `600`,
   заполните `PILOT_DOMAIN`, `DJANGO_SECRET_KEY` и `POSTGRES_PASSWORD`. Для пароля
   БД используйте длинную случайную строку из букв, цифр, `-` и `_`: Compose
   собирает `DATABASE_URL` из этих полей. Не добавляйте файл в Git или образ.
3. Оставьте `AI_ENABLED`, `TELEGRAM_PUBLIC_ENABLED` и
   `BILLING_ENFORCEMENT_ENABLED` выключенными до настройки ключей и проверок.
   Для пилота Telegram лучше создать отдельного бота: перенос webhook рабочего
   бота отключит получение событий стендом PythonAnywhere.
4. Используйте вымышленные сведения об объектах и клиентах. Встроенный пример
   имеет `is_demo=True` и не публикуется в Telegram. Для проверки этого пути
   создайте обычный объект с тестовым содержимым.

`.env.docker` используется и контейнерами приложения, и Compose при подстановке
переменных. Добавляйте `--env-file .env.docker` **к каждой** команде Compose.
Команда `docker compose config` без `--quiet` печатает подставленные секреты —
не отправляйте её вывод в чаты и журналы.

## Первый запуск

```sh
cp .env.docker.example .env.docker
chmod 600 .env.docker
# Отредактируйте .env.docker на VPS; секреты в чат не отправляйте.
docker compose --env-file .env.docker config --quiet
docker compose --env-file .env.docker up --build -d
docker compose --env-file .env.docker ps
docker compose --env-file .env.docker exec web python manage.py check --deploy
docker compose --env-file .env.docker exec web python manage.py createsuperuser
```

`check --deploy` может предупредить, что HSTS preload не включён. Для пилота
preload не требуется; решение о нём принимается после выбора постоянного домена.

`web` ждёт успешного завершения миграций и готовности Redis. `proxy` ждёт, пока
Gunicorn начнёт принимать соединения. Это проверка запуска процесса, а не замена
сквозным тестам пилота.

При обновлении выбранной ревизии запустите
`docker compose --env-file .env.docker up --build -d`: миграции снова пройдут
до замены `web`. Перед обновлением базы с пользовательскими данными сначала
проверьте резервную копию. Не выполняйте `docker compose down -v` на заполненном
стеке: команда удалит тома базы, фотографий и сертификатов.

## Что остаётся до приглашения тестировщиков

- Настроить расписание для `send_account_emails` (каждую минуту),
  `send_telegram_publications` (один экземпляр одновременно) и
  `send_overdue_tasks`. Этот Compose-файл сам не запускает их по расписанию.
  До отправки писем настроить SMTP.
- Сделать внешние резервные копии PostgreSQL и тома `media`, затем проверить
  восстановление. Существующая команда `backup_crm` поддерживает только SQLite.
- Проверить путь CRM → лендинг → заявка, выдачу фото, webhook и рассылку Telegram,
  генерацию OpenAI. Гонки тарифных ресурсов проверить на отдельной пустой
  тестовой PostgreSQL. До сверки счетов и этих тестов не включать ограничения.
- Настроить наблюдение за местом на диске, HTTP-ошибками, запуском команд и
  резервными копиями. Перед подключением публичного бота заменить его токен
  и секрет webhook, ранее отправленные в чат.

Приложение получает `X-Forwarded-Proto` и `X-Forwarded-For` только через Caddy.
Не открывайте порт Gunicorn в интернет и не добавляйте другой прокси без
проверки обработки передаваемых заголовков.
